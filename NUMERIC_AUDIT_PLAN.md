# Replay-11 numerical audit implementation plan

Goal: recompute the 33 preselected seed-42 cells from their frozen state without modifying a producer run.

1. Test the small pure checks first: frozen file SHA-256, batch identity, and unique inversion of four-decimal task accuracy. Include a wrong checkpoint, a wrong cache, and an ambiguous denominator.
2. In `replay11_numeric.py`, validate the already admitted job's frozen snapshot and source checkpoint paths using only relative paths and streamed content hashes. The frozen `formal_final.pt` is legitimately replaced during publication: use the PUBLISHED file hash for the bytes and require its trainer, method, and RNG state hashes to equal the frozen values. Read the recorded trajectory solely as the expected values.
3. Spawn a separate Python process against an explicit producer checkout at the job's actual commit. Materialize the authoritative test loader once into CPU batches, compare every batch with the sealed test-cache identity, and restore each stage snapshot and final checkpoint into fresh model and method objects.
4. Recompute diagonal and final Class-IL/Task-IL correct counts on the cache; invert each stored four-decimal value with the authoritative task total, demand one candidate, and compare integers. Recompute AA/BWT/Task-IL from the task integers at the producer's saved precision.
5. Run the synthetic ISOLET fixture and, if an accessible matching Linux host and data root are available, one read-only archived ISOLET/MIR/42 trial. Record wall time, peak memory, source commit, and any environment limitation. Commit only the numeric auditor, its test, and this plan locally.

The archived run's original inode, device, mtime, and absolute path are historical evidence. The upstream basic gate must bind any archive manifest; this numeric module verifies relative paths and SHA-256 and does not call a producer pinned-loader or training resume path. Stage checkpoint bytes are never collected into a list. Each checkpoint is streamed through one handle, loaded, evaluated, and released before opening the next. HPCR/iCaRL Task-IL integers are uniquely inverted from their newly computed four-decimal method readout; those values are not treated as producer-stored integers.

Read-only trial: on brf3080, the current source was streamed through stdin and executed against the completed `full-3080/isolet/mir/42` job, producer commit `467611a603c9604ad57861920495a3ad05612037`, authoritative ISOLET data, Python 3.11.15/Torch 2.5.1+cu124 in CPU mode. The final worker run reported 3.542 s and 657,305,600 peak RSS bytes; all 13 diagonal and final task integers matched the frozen readouts, and the three JOB_SUCCESS metrics matched exactly. A second HPCR seed-42 ISOLET trial exercised method-specific inference and reported 4.685 s with exact integer and metric agreement. These trials do not imply any other matrix cell has passed.

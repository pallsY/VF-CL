# CIFAR seed55 P0R1 scratch-loss recovery

The original v3 training-only run `cifar_seed55_P0R1` exited 0 and printed a development holdout readout. The host did not reboot, but all `/dev/shm` entries disappeared at 2026-10-13 18:55:52 CST, shortly after the run completed. Its frozen checkpoint, holdout manifest, and readout file were lost before a complete archive could be copied. The persistent launch log is retained and SHA-256 bound in the recovery manifest, but the log-only readout is **unverified** and excluded from all aggregates. No formal test was accessed or published.

A new training-only run uses the same locked source commit, seed, data, holdout design, and model parameters. Only `results_dir` and `output_dir` change to a fresh scratch root. Its launcher copies small audit metadata to the persistent result directory immediately upon successful completion before it reports exit 0. A full per-file archive is still required before the result is accepted and before its scratch files are cleaned. This recovery does not repeat a published formal test.

The first recovery did not begin training: a second host-wide `/dev/shm` purge at 19:06:36 CST removed its scratch root while the launcher was waiting. The launcher was stopped with exit 1; no recovery readout exists. The 3080 host remained up throughout both purges. Further runs must avoid that volatile volume until its cleanup owner is identified.

The 4090 host has byte-identical CIFAR train/test/meta files, the locked source commit, an idle GPU, and 13.4 GB available on its persistent root volume. A two-worker DataLoader smoke check succeeded with the current shared-memory availability. The remaining seed55 arms will use a fresh persistent result root there, one at a time, retaining the same model/seed/holdout fields. Config differences from the original v3 are limited to `data_path`, `results_dir`, and `output_dir`. Each arm requires local complete archive plus every-file hash verification before its host result directory is removed. Cross-host P1R1/P1R0 pre-head identity must be checked before treating that contrast as a valid pair; if unequal, the existing 3080 P1R1 result remains archived but cannot serve as the paired 4090 comparison.

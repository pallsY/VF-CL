# VF-CL 冻结代码复核与下一步（2026-10-19）

## 范围和事实基础

本次从实际生成结果的冻结提交重新检查：Replay11 基线生产 `467611a603c9604ad57861920495a3ad05612037`，原 adaptive `9973018295da270fd6098de07dcf36b9fe65ff61`，仅样本版 `e2a559dc4945729848225cf21fdc95451762c231`。三套原源码与结果均未修改。服务器最终门槛分别记录基线 99/99 基础＋33/33 seed42 数值复算、原 adaptive 9/9＋3/3、仅样本版 9/9＋3/3。冻结代码在 Linux 上运行了与样本版、PartyKD、延迟评估和最终头有关的 96 项测试，均通过；这证明受测流程可执行，不证明论文公式或方法表述完全正确。

数据文件哈希和四方划分与先前[关键因素核查](https://github.com/pallsY/VF-CL/blob/codex/key-factor-fairness-audit-v1/docs/superpowers/reports/2026-10-18-key-factor-fairness-audit.md)一致。ISOLET 四方列范围为 0–155、155–309、309–463、463–617；UPMC 为图像两方各 256 维和文本两方各 512 维。仅样本版各正式最终检查点每类恰有 20 个原始样本，`global_protos`、`prev_protos` 为空，训练期旧教师存在。测试读取发生在最终头安装后的一次正式访问；审计记录的是这些事实及数值一致性。

## 按影响程度排列的发现

### 1. [高] 蒸馏损失约束了尚未学习的类别

冻结 `cl_methods/proto_evolve.py` 的 `_proto_loss` 用 `n = min(old_logits.size(1), curr_logits.size(1))`，然后对 `[:, :n]` 计算全局 KL，并把 `list(range(n))` 传给方级蒸馏。三个数据集的任务 0 检查点里，分类头从一开始便分别有 CIFAR 100、ISOLET 26、UPMC 101 个输出；当时实际见过的类分别只有 10、2、11 个。因此任务 1 蒸馏同时覆盖了旧类、当前新类和尚未训练的未来类。代码注释称其为“旧类蒸馏”，与实现不符。未来类的教师输出不代表已学习知识；此前“关闭 PartyKD 后准确率下降”的消融只能证明**当前这整项损失**有效，尚不能把增益全部归因于旧知识保持。

应在新隔离版本里显式记录并只选择任务边界之前已学习的旧类索引，分别检验全局 KL 和方级损失的类别范围；先做公式级测试和两任务完整类别表试跑，再做新的训练集留出成对实验。任何修正后的结果不能复用旧 adaptive 的检查点或准确率。

### 2. [高] FIM 比例 0 的配置与实际执行不一致

原 adaptive 与仅样本版共 18 个正式作业的 `fim_freeze_frac` 都是 0.0，但冻结源码取最大 FIM 分位数后使用 `>=`，首次增量任务仍冻结每方一个参数张量：CIFAR 4/240，ISOLET/UPMC 4/16；仅样本版 ISOLET 的累计冻结后来到 5–6/16。旧准确率与审计仍对应真实代码，但不能称为“不冻结”。新开发分支已修正零值语义，ISOLET/UPMC 完整任务一轮预检证实 0/16；全预算归因队列正在等 3080 GPU 空闲。该队列仍采用旧蒸馏类别范围，其结果只说明旧方法中冻结的作用。

另需注意：`_compute_fim` 即使不冻结参数仍会运行；它将底层模型置于 `train()` 并遍历数据。CIFAR 的 ResNet 使用 BatchNorm，该遍历会更新运行统计量。因此当前新对照可称为“零**参数冻结**”，不能称为“完全不运行 FIM”。如果未来要移除 FIM 计算，还须单独检查 BatchNorm 状态和数据读取变化。

### 3. [高] CIFAR 主表只比较未做 BiC 校准的准确率

冻结结果文件同时保存最终主读数和 `bic_final.paired.calibrated`。主比较表取未做 BiC 校准的最终 CIL 分数。三个种子平均：仅样本版 37.99%（BiC 后 37.87%），ER-ACE 33.78%（BiC 后 34.85%），DER++ 20.71%（BiC 后 31.84%），ER 14.05%（BiC 后 31.72%）。所以仅样本版在两种口径下仍领先，但相对最强校准基线的差距为约 **3.02** 而非主表未校准口径的 **4.21** 个百分点；其他基线的排名也会改变。

论文需同时列出 CIFAR 未校准与全部方法 BiC 校准后的结果，明确主张采用哪一列。自有方法使用的最终头验证集合与基线 BiC 校准集合/阶段不同，不能把两列称为完全相同的验证访问。

### 4. [中] BWT 和“AA”名称容易误导

仅样本版的中间任务快照没有最终双分支头，最终一步才安装经过旧样本和验证集拟合的头。当前 BWT 用最终头后的各任务准确率减去首次学习时、尚无最终头的对角线准确率；例如 ISOLET seed42 报约 +77.83 个百分点。这既包含表示变化，也包含一次性的最终头提升，不能直接解释为“没有遗忘”或与每任务已有可用分类头的方法做同义比较。`AA_final` 是最终各任务均值，`AA_cil` 是整个增量过程各事件均值；二者也不能都简称“AA”。

建议正文以“最终 Class-IL 准确率”作为主指标；BWT 明确标记为当前流水线的公式读数，并补一项使用一致评估阶段的遗忘/旧类保持诊断，或不以它作核心优势论据。

### 5. [中] 原 adaptive 对比仅样本版不是单因素消融

正式配置同时改变 `sample_replay_only`、训练期原型回放梯度、`proto_sdc`（True→False）和特征蒸馏权重（0.05→0）。因此两版成绩之差不能只解释成“去掉原型特征回放”的作用。仅样本版保存 20 原始样本/类、训练期不把旧原始样本混入每批次，最终才重新编码并拟合分类头；每任务结束时仍用当前类嵌入计算临时统计并进行 herding 选样。论文名称应准确写作“仅原始样本记忆、最终头使用”，不要写成训练期 ER 式原始样本回放。

### 6. [中] 数据/计算与隐私边界要完整披露

ISOLET/UPMC 的 11 基线没有最终验证读取，自有方法分别读取 1,040/6,464 个带标签的训练集留出样本用于最终头；CIFAR 双方都使用 2,500 个校准/验证样本，但不是同一集合和阶段。名义 epoch 相同不等于总计算相同：自有方法还有教师前向、FIM 统计、选样遍历及 1,100 步最终头拟合。

当前单进程 VFL 模拟会加载完整拼接特征，并把 `head_raw_replay` 的拼接原始特征张量保存在中心训练进程。四方数值切分真实存在，但不能据此宣称已经实现“各被动方只在本地保存自己的原始特征”的部署隐私属性。若论文涉及这一主张，需要分方存储/访问证据。

## 建议的执行顺序

1. **锁定旧结果含义。** 保留全部旧提交、检查点、审计台账与 GitHub 锚点，在论文草稿/汇总表中增加 FIM 实际冻结、训练期旧样本使用方式、验证访问和 CIFAR BiC 双口径说明。旧审计通过意味着产物与源码一致，不意味着方法公式自动正确。
2. **优先修正蒸馏类别范围。** 在新的隔离代码和结果根里，给任务 1 加入“头宽度大于已学类别数”的回归测试；旧类索引只从此前任务记录产生。全局 KD 与 PartyKD 分别做损失/梯度单元测试和两任务预检。绝不覆盖冻结源码或结果。
3. **取得零冻结归因读数。** 现有后台队列在 GPU 空闲后会完成 ISOLET/UPMC 54/55 四项；它仍使用旧 KD 范围，只用于判断旧实现中参数冻结的影响。若失败，保留原始日志并停门。
4. **开发期成对验证修正版本。** 使用预定的新训练集留出种子与固定预算，比较旧 KD/修正 KD；再按零冻结读数决定是否保留冻结。不要继续在已经多次使用的 54/55 留出上反复选小变体。
5. **独立正式确认与公平展示。** 冻结最终方法后，用未参与开发的新种子与每数据集最强的若干基线做配对确认；CIFAR 同时给出全方法未校准和 BiC 校准结果。现有 42/43/44 正式表可作为历史实现结果保留，但不能替代修正版本的正式结果。新颖性只围绕经过消融证明的纵向联邦特有机制，不能把 [V-LETO](https://arxiv.org/html/2502.09152v2) 的原型/FIM、[iCaRL](https://openaccess.thecvf.com/content_cvpr_2017/papers/Rebuffi_iCaRL_Incremental_Classifier_CVPR_2017_paper.pdf) 的 herding 或 [BiC](https://openaccess.thecvf.com/content_CVPR_2019/papers/Wu_Large_Scale_Incremental_Learning_CVPR_2019_paper.pdf) 的验证校准本身当作新发明。

本次复核没有逐公式重新审阅 11 个基线的全部论文忠实性；它核验了其冻结提交、99/33 审计门槛、共同协议以及 CIFAR 主表/校准读数。基线公式忠实性如需论文级保证，应继续对照原论文和作者实现做独立专项复核。

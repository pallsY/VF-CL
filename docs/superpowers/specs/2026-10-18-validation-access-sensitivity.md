# VF-CL 最终验证访问敏感性对照：实施设计

## 目标与定位

已冻结的 11 基线和原 adaptive 在数据、四方划分、任务顺序、基础模型、批大小、当前任务样本读取与优化步数、一次性最终测试上对齐。原 adaptive 的双分支头另从训练集保留区读取 ISOLET 1,040 / UPMC 6,464 个验证样本；CIFAR 读取 2,500 个验证样本，而基线在另一预定集合上做 2,500 个 BiC 校准样本。这是 **方法的数据使用成本和潜在性能贡献**，主表应披露，不应默认为所有方法同样使用验证数据。

可选的补充对照用于回答窄问题：*原 adaptive 的最终双分支验证门控，对准确率贡献多少？* 它不替代忠实原方法，也不把不同算法强制改成完全相同资源。当前正式结果、审计、门槛、锚点保持冻结。

## 最小单因素改动

在新的隔离生产分支中保留原 adaptive 的 20 个原始样本/类、原型、冻结教师、PartyKD、FIM、四方模型、所有任务训练和 Full/Bias 候选拟合。唯一变化发生在**任务训练及双候选拟合后**：新对照预先固定混合系数 `g=0.5`，不读取用于求解 `g` 的最终验证集。`g=0.5` 是预先指定的敏感性点，不从 42/43/44 测试结果或 54/55 开发读数挑选。

固定门控仍需创建独立的、可严格重载的最终头与证据记录。现有 `adaptive_head_consolidation.py` 的 primary gate 证据和 `runner.py` 的正式阶段机强制要求验证迭代；直接把 `lambda_validation_enabled` 改为 0 会在源码/审计中失败，不能绕过检查或伪造验证 manifest。新对照必须有单独的 `fixed_half_no_validation` 协议身份、明确的无验证阶段转移和独立审计器公式。审计应重建冻结候选、验证固定 `g`、确认没有 `validation` 访问记录、严格重载最终头、复算指标并在失败处停止。

对 CIFAR，还须事先确定 BiC 校准：对照版本在头安装后仅使用与基线完全同一预定 2,500 样本的 BiC 校准集及相同步数；向量数据集没有 BiC。训练样本集合应与原 adaptive 和基线相同，不能因为关闭末阶段验证而把保留样本重新加入任务训练。训练数据索引、当前任务读取次数和正式训练检查点哈希应逐项核对。

## 开发、确认和结果解释

1. 在隔离代码与结果根中先做公式测试、两任务和完整任务低预算预检。若能从一个冻结的训练末状态分叉两种头，先独立证明分叉前模型与方法状态哈希一致，且任何测试访问发生在头冻结后。
2. 用预先指定的开发种子 54/55 和训练集留出样本检查流程、固定门控实现及稳定性；不使用旧 42/43/44 正式测试读数选择参数或候选。
3. 若对照有研究价值，先冻结新生产/审计提交、数据哈希、种子、预算与门槛，再用新种子 45/46/47 配对比较“原验证门控”与“固定无验证门控”。两者尽量共用相同的训练末状态以隔离头选择因素，分别记录一次性测试和独立数值复算。若要将新结果与某一基线作正式配对优势判断，该基线也须用相同新种子运行。
4. 以每种子的 CIL 最终准确率、BWT、Task-IL 及配对差值报告正负结果，同时列出最终验证/校准访问、头拟合、模型/记忆字节。不能把固定门控结果称为原方法的忠实复现；它是清楚标记的敏感性对照。

## 资源与启动边界

本设计先作为审查方案，不构成启动 GPU 训练的指令。只有新的阶段机、证据结构、独立审计、完整任务预检和预启动外部锚点准备好，才安排非重复的新对照。若设计成本超过其能回答的问题，主表可以沿用已经通过审计的 42/43/44 比较，同时明确报告验证访问差异并限制公平性表述。

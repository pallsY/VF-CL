# 四方互补信号只读分析协议（2026-10-21）

**目的。** 用已冻结的 ISOLET `reference20` 开发作业种子 54/55 和同一训练留出清单，描述分方任务证据是否呈现逐类差异、跨训练种子是否稳定，以及一个不依赖真实标签的固定置信度规则能否辨认可靠方。本分析不训练、不访问正式测试、不修改源目录，也不选择正式方法。

## 固定输入与输出

- 仅接受 `/brf/users/yangxx/VFCL-results/resource-lite-dev-full-v2-20261018/isolet_seed54_reference20` 和对应 seed55 的配置身份；两者的训练留出清单哈希必须相同，且配置、冻结标记、最终检查点、原留出读数哈希在运行前后不变。
- 复用既有 `diagnose_party_task_evidence.py` 的线性头分解：每方贡献是分类头权重在该方嵌入上的部分 logit，融合是各部分求和再加偏置。该分解对应审计 bundle 中的 `full_state` 分支；它不是四个独立训练的方分类器，也不自动等同于部署的双分支混合输出。
- 仅在进程内使用逐样本标签和 logit；持久化每类及每任务聚合计数、区间与总体汇总，不写逐样本标签、预测或任何可硬编码的模型权重。输出到新的独立诊断目录，源作业目录只读。

## 三项预定读数

1. **逐类差异。** 每个类恰有 40 个留出样本，记录四方任务识别正确数、准确率和 95% Wilson 区间；同时记录类内最高与最低方的差、同任务两类合并后的差。逐类范围可能因样本数较少而更大，不能单凭范围宣称有可利用的细粒度结构。
2. **跨种子稳定性。** 在相同类 ID 下报告四方正确率最高者跨 54/55 的一致比例、并列第一的类数，以及去除类均值和方均值后的 26×4 准确率残差相关。54/55 共享留出样本，因此这里只评估训练随机性下的重复性，不是独立数据验证。
3. **不知道真实标签时的识别。** 预先固定唯一主信号：每方任务 logit 的第一与第二大值之差，除以该样本该方所有任务 logit 的标准差加 `1e-6`。对每个样本选归一化间隔最大的方，预测其任务；选择过程不用真实标签。用标签**仅在事后**计算：所选方总体任务正确率、融合错误时救回比例、融合正确时损坏比例，并并列报告“至少一方正确”的 oracle 上限。另报告每方该间隔预测自身任务正确与否的 AUROC；不据此调阈值或重新选择信号。

## 解释与后续边界

- `fused_error_rescue_fraction` 是使用真值定义的 oracle 上限；乘以融合错误率才是全体样本中理论可救回的占比。任何实际规则还必须计入损坏原本正确样本的情况。
- 本次 54/55 分析是**假设生成**。哪个类、哪个方更可靠，以及任何在这两个种子上显示较好的阈值、权重、统计量，均不得直接写入最终机制或正式协议。若要设计新规则，必须先另行固定其公式，再用未参与本次分析的开发数据检验。
- 逐类差异稳定并不等于可部署；固定置信度规则若不能在不知道标签时提供可靠选择，就不能把 oracle 上限写成模型改进。原有任务汇总权重和四标量路由失败的原因仍需保留为未定。
